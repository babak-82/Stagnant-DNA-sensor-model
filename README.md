# Code for “Mass-transport limits of stagnant electrochemical DNA sensors: a reaction-diffusion analysis of response time and detection limit”

This repository contains the computational models, analysis scripts, and figure-generation workflow associated with the manuscript. The scripts are intended to reproduce the numerical analyses and figures described in the paper. Reproducibility should be assessed by running the complete workflow in the documented software environment; the presence of the scripts alone does not constitute independent validation of every reported result.

## Repository contents

| File | Description |
|---|---|
| `stagnant_cell_model.py` | Finite-volume solver for the reaction–diffusion model (stiff BDF integration), together with well-mixed and equilibrium references, surface-state calculations, and response-time calculations. |
| `lod_model.py` | Baseline model parameters, unit conversions, calibration calculations, limit-of-detection (LOD) calculations, and depletion-bound calculations. |
| `reproduce_all.py` | Main computational workflow. Runs the analysis stages and writes numerical outputs under `results/`, including JSON files and a claims summary. |
| `edge_effect.py` | Radial edge correction for a disk electrode using the Shoup–Szabo expression. |
| `make_figures.py` | Generates manuscript Figures 1–9 from the numerical outputs in `results/`. |
| `figstyle.py` | Shared figure styling and export utilities (PNG, PDF, and SVG). |
| `extra_checks.py` | Additional numerical checks for solver tolerance, Laplace-domain benchmarks, beta dependence, association-rate scenarios, probe-density optimisation, thermal estimates, and selected ratio ranges. |
| `requirements.txt` | Python package requirements used for the computational workflow. |
| `claims.md` | Snapshot of numerical claims and values associated with the manuscript. See the provenance note in that file. |
| `LICENSE` | MIT license. |
| `CITATION.cff` | Citation metadata for the software. |

## Software environment

The recorded environment for the project is Python 3.12.3 with the package versions listed in `requirements.txt`. Install the dependencies from the repository root:

```bash
python -m pip install -r requirements.txt
```

The versions in `requirements.txt` are pinned to the versions recorded for this project. Compatibility with other Python or package versions has not been established here.

## Reproduction workflow

Run commands from the repository root, in the following order:

```bash
# 1. Run the main analysis workflow
python reproduce_all.py

# 2. Run the additional numerical checks
python extra_checks.py

# 3. Generate the final figure set
python make_figures.py
```

The main workflow also supports the following options:

```bash
# Coarser grids for a quicker pipeline check; not a substitute for the full run
python reproduce_all.py --fast

# Run selected stages; stage names are listed in reproduce_all.py
python reproduce_all.py --stages validate,lod,fig1
```

To generate selected figures, provide their numbers, for example:

```bash
python make_figures.py 3 5
```

`make_figures.py` requires the numerical JSON outputs generated by `reproduce_all.py`. Therefore, run the main workflow before generating figures. The exact output paths are defined by the scripts; the main workflow writes numerical results under `results/`, while the figure-generation script writes the redesigned figure set under `results/figures_v2/`.

`extra_checks.py` is designed to be run after `reproduce_all.py`, because it reuses helper functions and selected outputs from the main workflow. It can also run selected checks, for example:

```bash
python extra_checks.py --stages tolerance,kon
```

The available additional-check stages are documented in the module docstring. Some stages require outputs from the main workflow.

## Reproducibility notes

- The model uses centimetres and moles internally in the relevant calculations. Unit conversions from the SI-valued baseline parameters are handled in `lod_model.py`.
- Random seeds are fixed in the scripts for the Sobol sequence, bootstrap calculations, and figure-level randomisation where applicable.
- The Sobol analysis stores intermediate evaluations in `results/sobol_evals.npy` and can resume from that file after an interrupted run. For a genuinely clean reproduction, remove prior generated outputs (including cached Sobol evaluations) before starting the full workflow.
- The figure styling prefers Inter when available and falls back to installed sans-serif fonts, including DejaVu Sans.
- `claims.md` is a recorded snapshot, not a substitute for regenerating the numerical results. After modifying code or parameters, rerun the analysis and compare the regenerated outputs with the manuscript before making a release.
- A fast/coarse run is intended for checking that the workflow executes; it should not be used as the source of final manuscript values.
